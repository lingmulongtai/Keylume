# v0.6.1 検証記録

2026-10-13。Windows x64、Launchkey MK4 61向けPreview。アプリの自動テスト、実機へ接続した診断、ユーザーが行った物理操作の結果を分けて記録します。

## アプリの検証

- Vitest: 9ファイル、28テスト成功。Playwright: 19テスト成功。TypeScript / Viteのproduction build成功。Rustライブラリは107テスト成功、外部GitHubへ接続する1テストのみ明示的に除外しました。Rust fmt、全ターゲットClippy（警告をエラー扱い）、ライセンス342件の再生成差分なし。
- Windows用の分離した検証ビルド（通常版と異なるidentifier・設定保存先）を作成し、実機の通常MIDI・DAWポートに接続できました。本体の機種識別応答 `00 20 29 46 01` を受信しました。これは押下や発光の合格を意味しません。
- Rustの入力・照明・OLED・音声回帰テストを追加しました。120秒相当の音声を4種類のサンプルレートで処理し、ノブ設定を繰り返し変更する単独テストに成功しました。10kHzの試験音にDriveをかけた際の18kHz折り返し成分と10kHz成分の比は、旧方式の約0.243から新方式の約0.000039へ低下しました。これは合成試験音での結果であり、全音色の聴感評価ではありません。
- 実機ポートへ接続した検証ビルドと、MockDeviceによる配布バイナリ自己テストを混同しません。配布の `verification.json` にも `hardwareTested=false` を残します。

## 実機で確認した信号と残る制約

利用者が本体を物理操作した診断では、DAWポートのチャンネル1で中央左 CC103、中央右 CC102、パッド左上 CC106、下 CC107、Record CC117、Undo CC77、Metronome CC76の押下／解放を記録しました。v0.6.1の分離した検証ビルドでも7操作すべてのボタンIDを受信しました。中央左右ではライティングのプリセットが実際に `neon → sunset → neon` と切り替わり、続けて押した際にも切り替わりました。ScaleとArpはFeature Controlsの状態通知、ShiftはDAWポートの通知を記録しました。検証ビルドでは楽器をオフにしていたため、Record・Undo・Metronomeによる録音や音声は未判定です。パッド左上下のドラムキット変更とOLED表示の視認も、この記録だけで合格とは判定しません。

ノブ右側の上下ボタンでは独立した入力を記録できませんでした。対応候補CC51/52へのチャンネル4のCC方式とNote On方式、パレット番号を変えた2通りのLED診断でも、利用者は「両方光っていません」と報告しました。したがってこの2ボタンの操作・点灯は未対応です。Scale・Arp・Chord Map・Fixed Chord・Settings等、本体管理のボタンの標準動作と表示を完全に上書きする保証もありません。これらの割り当ては標準で無効にし、実験的な設定を明示した場合だけ試せます。

音源の高低域の品質には、同梱・追加サンプルの音域とRustySynthの再生方式による限界が残ります。今回のDrive改善は音源サンプル自体を差し替えるものではありません。音声の無音化やOLEDの全数値のちらつきが実機で完全に解消したとする長時間の聴取・視認試験は未完了です。
